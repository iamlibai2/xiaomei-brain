# Desktop UI 审计与重构方向

> 日期：2026-07-28  
> 状态：讨论稿，尚未开始代码改造  
> 本次结论来自 xiaomei-brain Renderer 源码审计，以及本机 WorkBuddy 安装包中
> Renderer 代码与样式的只读对照。涉及实际观感的判断仍需在真实 Desktop 中共同确认。

## 1. 结论

Desktop 目前已经具备完整的产品主链路，但界面仍混合着三个阶段留下的设计：

1. 早期 WorkBuddy 风格首页模板；
2. 多 Agent 聊天与会话管理；
3. 新增的 Activity、Assignment、Artifact、Memory 和 Agent State 观察系统。

问题不是“界面不够华丽”，而是这三套信息架构尚未收束。最优先的工作应是去掉虚假入口、
重新建立视觉层级，再进行颜色、圆角、动效等美化。

第一轮重构不修改 Gateway、数据库或 Agent 领域模型，只调整 Desktop Renderer。

## 2. 源码审计事实

当前 Renderer 规模：

- 32 个 TSX 文件，约 5049 行；
- 11 个 CSS 文件，约 5467 行；
- `home.css` 2798 行；
- `ActivitySidebar.tsx` 941 行；
- `HomePage.tsx` 865 行；
- `sidebar.css` 937 行；
- 已有 649 行 Design Tokens，但通用 UI 组件主要只有 Button 和 Icon。

这说明当前已经有一套颜色、间距和字体变量，却缺少能约束页面实现的组件层。大量页面继续
直接写 CSS，导致 Token 很完整、界面语言仍然容易分叉。

### 2.1 已经露出但没有真实行为的入口

源码中可以确认：

- 左栏搜索按钮没有行为；
- 会话内搜索按钮没有行为；
- 首页快捷操作没有行为；
- “成长伙伴”操作按钮没有行为；
- 工作区与权限下拉没有行为；
- 输入框“自动模式”下拉没有行为；
- 语音输入按钮没有行为；
- 通知铃铛没有行为；
- DevTools 菜单没有行为；
- 首页积分横幅没有实际业务。

这些入口会直接损害可信度。Agent 的能力应当诚实，不能用可点击外观表达不存在的能力。

### 2.2 首页仍有模板语义

首页包含：

- “工作 / 编码 / 设计”场景切换；
- 文档、财务、数据分析快捷入口；
- 猫咪成长伙伴；
- 积分提示；
- 固定的 `xiaomei-brain` 大标题。

它们更像通用 AI 工具或 WorkBuddy 模板，没有表达当前产品最独特的内容：

- 这是一个具体、独立的 Agent；
- 它有名字、职责、关系、状态和持续经历；
- 它可能正在工作、整理记忆、反思或梦境；
- Person 是在继续与“这个 Agent”相处，而不是打开一个功能集合。

### 2.3 三栏结构正确，中间主区的边界需要整理

当前宏观布局本身是正确的：

```text
自定义菜单栏 30px
┌──────────┬──────────────────────────┬──────────────┐
│ 左栏260  │ 整个 HomePage 最大800px  │ 右栏380px    │
│ Agent    │ 顶栏、消息、输入框均在内 │ 六个横向标签 │
│ Session  │                          │              │
└──────────┴──────────────────────────┴──────────────┘
```

不需要重写三栏或重新抽象一套 Shell。需要调整的是 `wb-home-page` 对整个中间区域设置
`max-width: 800px` 和页面级 padding，导致 Chat Topbar 也被当作正文内容约束。
中间主区的正确边界应该是：

- 中间主区域填满剩余空间；
- Chat Topbar 横跨整个中间区域；
- 只有消息正文和输入框使用合适的阅读宽度；
- 右栏是独立 Inspector，不参与正文宽度计算。

当宽度小于 1050px 时右栏会变成绝对定位浮层，但当前没有统一的遮罩、拖拽缩放、
Escape 关闭和明确的浮层层级。

### 2.4 左栏承担了过多直接操作

Agent 行同时展示：

- 头像；
- 名字；
- host/port/PID 或状态；
- 启动、重启和停止按钮；
- 状态点；
- 未读数。

运维动作与日常切换混在同一视觉层，列表会显得忙乱，也容易误触。Agent 多起来后，
Agent 列表还会直接挤压会话列表。

### 2.5 右栏内容正确，但导航过密

380px 右栏顶部同时放置：

- 动态；
- 状态；
- 委托；
- 产物；
- 记忆；
- 上下文。

六个横向文字标签还附带数量，在较窄宽度下可读性和点击面积都不足。内容本身有价值，
问题是缺少分组：

- 动态属于“现在发生什么”；
- 状态属于“Agent 现在是什么状态”；
- 委托与产物都属于“工作”；
- 回答召回与长期记忆都属于“记忆”；
- 上下文是暂时保留的诊断/解释入口。

### 2.6 视觉语言存在分叉

- Token 以薄荷绿为品牌色；
- Activity、梦境、Artifact、Assignment 又分别直接使用多组蓝、紫、棕和橙色；
- 多个 Dialog 各自实现遮罩、阴影、按钮和表单；
- `home.css` 同时包含聊天、右栏、委托、消息、Markdown、附件和状态页；
- 同一种“卡片、状态、空页面、标签页”被重复实现。

品牌色本身没有问题，但需要建立稳定语义：

- 薄荷绿：在线、当前选择、Agent 的生命感；
- 蓝色：工作与执行；
- 紫色：认知、反思和梦境；
- 橙色：等待与需要注意；
- 红色：失败与危险；
- 灰色：普通结构与非活动状态。

颜色不应由每个页面临时决定。

### 2.7 字号和可访问性

`home.css` 与 `sidebar.css` 中有 83 处 9px、10px 或 11px 字号。少量计数徽标可以使用
10px，但状态说明、记忆来源、活动步骤和元数据长期使用 9px–10px 会明显影响阅读。

另外：

- AgentItem 和 SessionItem 使用可点击 `div`，不能自然通过键盘访问；
- 多数图标操作依赖原生 `title`，缺少一致 Tooltip；
- 缺少统一 `focus-visible`；
- 多处按钮没有显式 `type="button"`；
- Hover 承担较多信息，但没有统一的键盘等价行为。

## 3. WorkBuddy 本机版本对照

本机安装位置为 `D:\Program Files\WorkBuddy`。其 Electron `app.asar` 中可以确认：

- 外层使用横向 Flex 工作区；
- 左侧助理抽屉固定宽度为 264px；
- 左栏支持固定、收起和 Hover 悬浮预览三种状态；
- 中间 Agent Chat Pane 填满剩余空间；
- Chat Topbar 固定高度 56px 并横跨 Chat Pane；
- 消息和输入区的内容宽度使用 832px 上限；
- 右侧 Detail Panel 与主区分离；
- 右侧面板的开关和窄模式按会话缓存；
- 空会话页展示助理头像、标题、职责说明和真实建议；
- 左栏背景、聊天背景和 Detail Panel 依靠背景层级区分，不大量使用阴影。

因此，xiaomei-brain 不需要重新发明整体布局，也不需要改成另一种结构。现有三栏与
WorkBuddy 已经高度接近，应该直接复用它已经验证过的边界：

```text
左栏 260–264px │ Chat Pane 填满剩余空间 │ 可开关的 Detail/Inspector
               │ ├─ 56px 全宽 Topbar     │
               │ ├─ 受限宽度的消息正文   │
               │ └─ 受限宽度的输入区     │
```

需要学习的是布局行为，而不是照搬 WorkBuddy 的积分、宠物、企业入口或任务产品语义。

## 4. 建议的信息架构

```text
┌─────────────────────────────────────────────────────────────┐
│ 轻量窗口栏：应用菜单 / 当前 Agent / 窗口控制               │
├────────────┬──────────────────────────────┬─────────────────┤
│ Agent 导航 │ 会话主区                     │ Agent Inspector │
│            │                              │                 │
│ Agent 列表 │ 会话标题 + 轻量状态          │ 动态 / 状态     │
│            ├──────────────────────────────┤ 委托 / 产物     │
│ 当前 Agent │                              │ 记忆 / 上下文   │
│ 的会话     │ 消息正文（限制阅读宽度）     │                 │
│            │                              │                 │
│            ├──────────────────────────────┤                 │
│ Person     │ 固定输入区（限制阅读宽度）   │                 │
└────────────┴──────────────────────────────┴─────────────────┘
```

### 4.1 左栏：导航，而不是运维面板

- Agent 列表设最大高度并独立滚动；
- 当前 Agent 更清楚地高亮；
- 默认只展示头像、名字、当前状态和未读数；
- 启动/停止/重启收进 Hover 菜单或 Agent 设置；
- 会话列表占据剩余空间，继续按最近使用自然排序；
- 新会话保持明显，但不使用“项目/任务”术语；
- 折叠后显示 Agent 头像和状态，不显示宿主机细节；
- 可参考 WorkBuddy，在收起状态 Hover 时临时浮出完整列表，但第一轮可以不做；
- host、port、PID 放入 Agent 设置或诊断页。

### 4.2 中间：对话始终是第一主角

- 主区取消整体 `max-width: 800px`；
- 参考 WorkBuddy，顶栏以 56px 高度横跨 Chat Pane，只显示会话名、Agent 轻量状态和必要操作；
- 消息正文和输入区使用同一宽度变量，第一版可采用 WorkBuddy 的 832px；
- 输入框与消息正文对齐并固定在底部；
- 连续的 Agent 消息可以共用一次头像与名字，减少重复；
- Tool、Clarify、Action、Artifact、Assignment 使用统一的“会话事件卡片”外壳；
- Thinking、工具过程和元数据使用渐进展开，不抢正文；
- 排队、处理中、失败、中断等反馈靠近对应消息。

### 4.3 首页：回到具体的 Agent

移除积分、猫咪和无行为快捷入口。空会话页建议只保留：

1. Agent 头像、名字和职责；
2. 当前生命状态与一行自然语言状态；
3. 与当前 Person 的一行关系提示；
4. 输入框；
5. 2–3 条来自 Agent 真实能力的建议，例如“继续最近的工作”或“把文件交给我看看”。

建议内容必须来自真实状态或能真正填入输入框，不能只是装饰。

### 4.4 右栏：统一 Agent Inspector

右栏继续保留六个现有入口：

1. **动态**：正在发生和最近完成；
2. **状态**：生命周期、关系、心情、身体、欲望和激素；
3. **委托**；
4. **产物**；
5. **记忆**：本次回答召回与当前 Person 长期记忆；
6. **上下文**。

现阶段不合并“委托/产物”，也不迁移或关闭“上下文”。六个栏目是否取舍留到真实使用一段
时间后再讨论。关系继续位于状态页第二部分，符合当前已确定的优先级。

右栏还应：

- 支持拖拽调整宽度；
- 记住每个 Agent 的打开状态与宽度；
- 窄屏使用带遮罩的抽屉；
- 支持 Escape 关闭；
- Header 不重复显示过多与 Chat Topbar 相同的信息。
- 参考 WorkBuddy，按 Agent/会话保存展开状态、当前栏目和宽度。

## 5. 视觉方向

不建议做成赛博朋克或浓重科技风。这个产品的差异不是“像机器”，而是 Agent 有持续生命。

建议使用：

- 大面积温和的中性浅灰和白色；
- 薄荷绿作为生命、在线和选中态；
- 蓝/紫只用于工作与认知的语义区分；
- 更少的边框，更明确的背景层级；
- 卡片圆角统一为 8px/12px 两档；
- 浮层才使用阴影，普通内容卡片主要依靠背景和间距；
- 正文 14px，辅助信息不低于 12px，只有徽标允许 10px；
- Agent 头像保留个体化空间，未来可以支持每个 Agent 的头像和主题色；
- 动效只表达状态变化：开始工作、消息排队、梦境、右栏展开，不做无意义漂浮。

## 6. 组件重构

不引入大型 UI 框架，先在现有 React/CSS 基础上建立最小组件层：

- `AgentListItem`
- `SessionListItem`
- `Inspector`
- `InspectorNav`
- `PanelHeader`
- `Tabs` / `SegmentedControl`
- `Card`
- `StatusBadge`
- `Progress`
- `EmptyState`
- `Tooltip`
- `Dialog`
- `Field`
- `ConversationEventCard`

同时拆分样式：

```text
styles/
  foundations/
    tokens.css
    reset.css
  shell/
    app-shell.css
    left-sidebar.css
    inspector.css
  chat/
    conversation.css
    composer.css
    message.css
    event-card.css
  features/
    activity.css
    assignment.css
    artifact.css
    memory.css
    state.css
  overlays/
    dialog.css
    terminal.css
```

目标不是为了拆文件而拆文件，而是避免 `home.css` 继续成为所有功能的公共堆放区。

## 7. 建议实施顺序

### 阶段 A：界面诚实性

- 删除已经确认不属于产品的模板入口；
- 搜索、语音、模式和通知等计划接入真实能力的入口保留，后续逐步实现；
- 清理积分、成长伙伴和模板场景；
- 修复 DevTools、搜索等入口的“能点但无反应”问题；
- 不改变现有业务链路。

这是风险最低、体验收益最高的一步。

实施记录（2026-07-28）：

- 已移除积分横幅；
- 已移除猫咪成长伙伴；
- 已移除工作、编码和设计场景；
- 已移除文档、金融、数据分析等无行为快捷入口；
- 已移除无行为的工作区与默认权限栏；
- 已删除对应组件、文案、样式和仅为场景切换存在的 Store 状态；
- Desktop Main 与 Renderer 完整构建通过。

搜索、语音、模式和通知由产品设计明确保留，后续逐步接入真实能力，不再作为本轮清理对象。

### 阶段 B：会话主区边界整理

- 保留现有 `MainShell` 和三栏结构；
- 让 Chat Topbar 横跨中间主区；
- 参考 WorkBuddy，用同一个 832px 变量约束消息和输入框；
- 固定 Composer；
- 完善右栏窄屏抽屉；
- 保持左栏和右栏现有功能不变。

实施记录（2026-07-28）：

- 保留现有 `MainShell` 和三栏结构；
- Chat Topbar 改为横跨完整 Chat Pane；
- 消息正文、委托条和 Composer 统一使用 832px 内容边界；
- 会话滚动容器与内容宽度解耦；
- 空会话页改为展示当前 Agent 的头像、名称、职责和真实状态；
- 梦境排队提示分别适配空会话与已有会话；
- 增加 640px 以下的独立边距规则；
- Desktop Main 与 Renderer 完整构建通过。

### 阶段 C：右栏重构

- 保留动态、状态、委托、产物、记忆、上下文六个入口；
- 不改变现有信息架构，只统一标题、导航、卡片和空状态视觉；
- 召回记忆/长期记忆统一视觉；
- 拆分 941 行的 `ActivitySidebar.tsx`。

实施记录（2026-07-28）：

- 六个栏目及其业务逻辑全部保留，没有合并或迁移；
- 顶部改为 Agent 身份、连接状态、生命周期状态和当前活动的分层展示；
- 六栏目导航统一为图标、文字、数量角标和明确选中态；
- 提升动态、状态、委托、产物、记忆、上下文的正文与元数据可读性；
- 右栏在窄窗口下改为带遮罩的抽屉，可点击遮罩或按 `Esc` 关闭；
- 补充键盘焦点样式；
- Desktop Main 与 Renderer 完整构建通过。

本阶段剩余的组件拆分属于代码维护工作，不影响当前界面体验，留到 Design System
收束时与 `home.css` 拆分一起处理。

### 阶段 D：左栏与会话

- Agent 导航与会话区域明确分层；
- 运维动作收进菜单；
- Agent 区独立滚动；
- 修正可点击 `div`；
- 增加统一 Tooltip、键盘导航和 Focus。

实施记录（2026-07-29）：

- Agent 列表与当前 Agent 的会话列表形成独立区域，并分别滚动；
- 加强当前 Agent、当前会话、在线状态、工作状态和未读数的视觉层级；
- 折叠左栏后继续显示 Agent 未读数；
- Agent 与会话条目支持键盘选择并补充清晰的焦点状态；
- 清理会话区域的内联布局样式，统一由 `sidebar.css` 管理；
- 会话保持按最近更新时间自然排列，不再因被选中而移动到顶部；
- 取消“当前、今天、昨天、更早”分组，每条会话直接展示统一日期；
- 取消左栏独立会话搜索，后续与全局搜索统一设计；
- 本轮按产品决定不调整启动、停止和重启相关入口；
- Desktop Main 与 Renderer 完整构建通过。

运维动作的进一步收束需要单独讨论本地 Agent 管理方式，本阶段不处理。

### 阶段 E：消息与卡片

- 统一会话事件卡片；
- 优化连续消息分组；
- 统一工具、Clarify、Action、Artifact 和 Assignment 状态；
- 收敛 Markdown、Thinking 和代码块样式；
- 提高元数据字号和对比度。

实施记录（2026-07-29，第一轮）：

- 普通消息减少过大的垂直留白；
- Agent 头像改为与整体界面一致的柔和方形样式；
- Clarify、Action、Artifact 和 Assignment 统一为克制的平面卡片边界；
- 移除 Clarify 卡片阴影和 Action 卡片渐变；
- 工具调用改为紧凑状态行；
- Thinking 详情移除强调竖线，改用轻量内容容器；
- 补充卡片按钮的键盘焦点状态；
- 未改变交互协议、状态流转或卡片业务行为；
- Desktop Main 与 Renderer 完整构建通过。

连续消息分组和 Markdown/代码块细节留待实际界面验证后继续，避免一次改动过多。

### 阶段 F：Design System 收束

- 提取通用组件；
- 清理硬编码颜色；
- 拆分 `home.css`；
- 统一 Dialog、表单、空页面、Badge 和 Progress；
- 做 100%、125%、150% Windows 缩放与窄窗口验收。

## 8. 第一轮不做

- 不修改 Agent/Gateway 协议；
- 不增加新业务功能；
- 不做深色模式；
- 不引入大型组件库；
- 不做换肤系统；
- 不为了“高级感”加入粒子、玻璃拟态或复杂动画；
- 不把 Desktop 变成项目管理看板；
- 不重新引入会话归档和复杂整理功能。

## 9. 推荐起点

建议先实施阶段 A，再做阶段 B。

原因是当前最影响体验的不是细节样式，而是：

1. 一些入口承诺了不存在的能力；
2. 首页表达的不是“小美是什么”；
3. Chat Topbar、消息与输入框没有形成稳定的主区骨架。

这两步完成后，真实界面会先从“功能拼装页”变成清晰的 Agent 对话工作台，之后再重构右栏
和视觉细节，返工会明显减少。
