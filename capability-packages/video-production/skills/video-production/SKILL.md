# 视频制作

## 定位

视频制作是一个持续项目，不是一次模型调用。你负责保存真实进度、组织素材、明确等待原因，
并只把经过验收的成片作为最终交付物。

不要假装调用了不存在的模型，不要把策划稿称为成片，不要因为视频生成服务不可用而丢掉已经
完成的编导、分镜和素材工作。

## 选择交付标准

Project 阶段是你自己的工作地图；Process 是本次工作必须正式提交什么。不要把二者混为一谈。

先调用 `list_project_process_templates` 查询当前项目可用的标准，再按模板 ID 调用
`apply_project_process_template`。普通完整视频默认选择 `video-fast-3`；用户明确要求八阶段、逐阶段确认、
正式制作或完整过程时，必须选择 `video-full-8`，不能用三阶段标准代替。

用户明确说“X 阶段交付标准”时，这是一项正式约束：创建 Project 后必须先建立真实 Process，才能建立或更新
Project 阶段。若模板列表中没有完全匹配的阶段数，使用 `define_project_process` 按用户要求定义，不得用相同数量的
`set_project_step` 冒充 Process，也不得只在项目摘要或最终回复中声称已经采用该标准。

模板的完整阶段和要求由独立 Process 文件维护，不要从 Skill 复制 JSON，也不要自行重写或删减。用户提出模板以外的
交付要求时，才通过 `define_project_process` 定义更合适的标准；不要强迫所有视频套用模板。

完整八阶段是正式提交标准，不是你的执行顺序。它要求按顺序正式提交，但你仍可自由组织内部工作。

每次正式提交使用 `submit_process_stage`。提交只证明明确要求的资产或事实已经存在，不代表工具替你评价创作质量。
Process 不适合当前目标时，应根据用户决定修订定义，而不是伪造证据或机械补齐无意义产物。

## 何时进入项目和委托

以下任一情况成立时，先创建 `video.production` Project，再创建项目范围的 Assignment：

- 需要多个镜头；
- 预计总时长超过 15 秒；
- 同时包含画面、口播、音乐、字幕中的两种以上；
- 需要等待生成、渲染或用户分阶段确认；
- 用户要求企业可交付成片。

单个短镜头试验可以直接调用视频生成工具；持续的视频制作工作应使用 Project 保存现场。

## 参考认知地图

常见视频制作可能涉及需求、编导、分镜、视觉素材、动态镜头、声音、合成和验收，但这八项只是领域经验，
不是所有视频都必须经过的固定流程。默片可以没有声音阶段，已有素材剪辑可能不需要视觉生成，短视频也可以把
编导与分镜合并。

调用 `initialize_video_project` 只建立工作目录并保存需求简报，不会替你建立阶段。根据用户目标和现场需要，
使用 `set_project_step` 建立当前项目自己的阶段地图；可重命名、重排和新增阶段，也可使用
`remove_project_step` 合并或移除不再适合的阶段。不要自行在源码目录创建工作文件。

阶段不是依次通过的关卡。可以并行推进、回到前面的判断或改变计划；关键是项目记录应反映 Agent 对当前现场
的真实认识，而不是为了填满进度条机械更新。

## 项目复盘

在以下自然节点调用 `review_project`，一次性校准项目，而不是逐项机械打卡：

- 需求、编导和分镜已经形成时；
- 用户确认或否定分镜、样片、候选成片时；
- 实际素材、时长、声音或镜头数量偏离原计划时；
- 准备交付候选成片或宣布项目完成前。

复盘基于用户原话、已登记资产、媒体检查和工具结果。`steps` 只更新本次能够确认的判断；没有证据的阶段保持
原状态。计划改变时写入 `plan_changes`，实际结果与用户目标存在有意义的差异时才写入 `deviations`。

恢复旧项目或收到“确认”“定版”时，先用项目记录和已登记资产核对候选成片。已有交付物满足用户决定时，
直接复盘并收束，不要为了更新阶段状态再次生成镜头或重新合成视频。

`compose_video_timeline` 会返回 `evidence`，其中包括计划时长、实际时长、分镜中的声音安排和成片是否存在
音轨。这些是客观事实，不是自动验收规则。结合用户要求判断它们是否构成问题：用户要求默片时无音轨是正确
结果；用户要求配乐而成片无音轨时才需要继续处理。不要捏造与工具证据冲突的事实。

复盘不会规定下一步必须做什么。由你根据当前结果填写 `next_action`，继续自主完成项目。

## Clarify 边界

仅在答案会明显改变最终作品时询问：

- 横屏、竖屏或方形；
- 目标时长和发布平台；
- 受众及最重要的一句话；
- 视觉风格、品牌色和必须使用的素材；
- 是否需要口播、音乐、字幕；
- 涉及人物肖像、声音或商标时的授权确认。

一次尽量集中确认，不要为低价值参数连续打断用户。若用户已明确说明，就直接继续。

## 分镜规范

调用 `save_video_storyboard` 时传入 JSON 数组。每个镜头使用：

```json
{
  "id": "shot-001",
  "duration": 4.5,
  "visual": "画面主体、动作、构图、光线和运镜",
  "narration": "本镜头口播，没有则为空",
  "transition": "cut",
  "audio": "环境声或音乐提示",
  "status": "planned"
}
```

分镜总时长应接近 brief 的目标时长。先让用户确认结构和风格，再批量生成高成本素材。

## 素材规则

- 当前消息附件先调用 `stage_video_asset`，之后把返回的 `media_path` 原样传给媒体工具。
- `media_path` 必须指向一个具体文件，例如 `clips/shot-001.mp4`；不能传目录、`.`、绝对路径，
  也不要用 Shell 或 Glob 重新寻找已经登记的素材。
- 使用 `inspect_video_media` 获取真实时长、分辨率、帧率和音频流，不凭文件名猜测。
- 使用 `create_video_contact_sheet` 形成快速审阅图；它是 review 资产，不是最终产物。
- 外部视频生成工具必须传入分镜的 `scene_id`；结果会进入项目 `motion/`，并登记为工作资产，
  不会冒充最终交付物。
- 大量中间素材只进入项目工作区；不要逐个发送到聊天，除非用户正在确认该样片。

## 生成模型不可用时

视频生成服务未配置、欠费或无权限时：

1. 保留已完成的 brief、编导和分镜；
2. 继续整理用户已有的图片、视频、口播和音乐；
3. 将 `motion` 明确标记为等待，说明缺少的具体素材；
4. 可以使用静态图片、文字动画和已有视频走 FFmpeg 路线；
5. 不重复提交可能计费的任务，不把失败说成排队中。

## MiniMax 视频参数

- `MiniMax-H3`：4～15 秒，固定使用 768P；不要选择 2K，避免不必要的生成费用。
- `MiniMax-Hailuo-2.3`：只支持 6 秒或 10 秒，支持 768P 或 1080P。
- 分镜短于模型最小时长时，生成允许的最短时长，再把每个目标镜头时长作为
  `clip_durations` 交给 `compose_video_timeline`；不要反复提交无效参数。
- `query_video_minimax` 成功后直接使用其 `media_path`，不要把项目资产 ID 当成附件 ID，
  也不要再次调用 `stage_video_asset`。

## 合成

调用 `compose_video_timeline` 前确保：

- clips 的顺序与分镜一致；
- `clip_durations` 与 clips 一一对应，模型生成片段过长时据此裁剪；
- 所有路径都是项目工作区相对路径；
- 字幕为 UTF-8 SRT；
- 口播和音乐已经过试听；
- 横竖比、宽高和帧率符合发布渠道。

工具会统一尺寸、帧率和像素格式，默认保留所有片段都具备的原始音轨，并生成 H.264/AAC MP4。候选成片进入
`deliverables/`，工具只登记文件和媒体事实，不会替你修改阶段或宣布项目完成。应结合实际结果和用户目标，
由你通过 `review_project` 更新认知地图。

## 验收

技术验收至少核对：

- 文件可读取且有视频流；
- 时长与目标接近；
- 分辨率、宽高比和帧率正确；
- 需要声音时存在音频流；
- 字幕没有明显截断或越界；
- 没有黑帧、长时间静帧、爆音或异常音量。

观看验收至少核对：

- 开头能快速说明主题；
- 叙事逻辑和节奏清楚；
- 画面、口播、字幕语义一致；
- 品牌、人物、数据和文字准确；
- 结尾完成用户需要的行动或结论。

必须明确区分三种结论：FFprobe、文件解析等只能证明技术事实；视觉模型实际读取画面后才能称为模型视觉检查；
用户明确看过并确认后才能称为用户观看确认。视觉模型未启用、文件未被实际打开或用户尚未确认时，只能说明已完成的
技术检查，不得声称“画面已经看过”“视觉效果正确”或“观看验收通过”。

在准备交付或用户反馈后，调用 `review_project` 对照真实成片和用户决定更新项目判断。目标已经实现时可以将
Project 标记为完成；若要求修改，保留同一个 Project，更新原有工作资产和候选成片，不创建重复项目。
